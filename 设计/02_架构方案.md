# 架构方案 · 项目分层

> 版本 v1.2（2026-09-28 维护） · 依赖需求文档 §2-§5；目录与数据结构已同步至 E17 后实际状态

## 1. 设计原则

1. **时点纪律优先于一切**：任何因子函数只允许访问「信号日及以前」的数据，由数据层的时间参数强制约束，而不是靠使用方自觉。
2. **数据与计算分离**：抓取（慢、限流、可重试）与回测（纯内存计算）彻底解耦，中间以本地 parquet 缓存交换。
3. **双环境协作**：`qlib_ifind_beta`（requests，负责 iFinD 池抓取与 select_today 输出）与 `resonance`（vectorbt 1.1.0，负责回测）互不安装新包，通过文件交付。
4. **探索友好**：每个实验脚本是自包含入口，输出图表+指标到 `reports/`，重跑幂等（缓存命中即跳过抓取）。

## 2. 分层结构

```
┌─────────────────────────────────────────────────────────┐
│ L5 实验层  scripts/exp_*.py、scripts/select_today.py    │  ← 用户入口
├─────────────────────────────────────────────────────────┤
│ L4 回测层  backtest.py  (vectorbt)                      │
│    信号→订单、T+1、成本模型、组合统计                      │
├─────────────────────────────────────────────────────────┤
│ L3 选股层  select.py                                    │
│    因子打分/排序/确认过滤 → 每日目标持仓 Top-N            │
├─────────────────────────────────────────────────────────┤
│ L2 因子层  features.py                                  │
│    日频因子(T-1) + 盘中9:35因子(T)，全部向量化            │
├─────────────────────────────────────────────────────────┤
│ L1 数据层  ifind_pool.py / bars.py / cache              │
│    iFinD成分池、qlib仓行情导出、parquet缓存           │
├─────────────────────────────────────────────────────────┤
│ L0 配置    config.py                                    │
│    池代码、窗口、成本、TopN、路径、token                  │
└─────────────────────────────────────────────────────────┘
```

**调用方向**：L5 → (L4 → L3 → L2 → L1)。禁止跨层反向调用；L2 以上不出现任何网络请求。

## 4. 关键数据结构（层间契约）

### 4.1 成分池 `data/raw/pools/pools.parquet`

| 列 | 类型 | 说明 |
|----|------|------|
| date | datetime64[D] | 池子快照日（=T-1） |
| pool | str | `883910` / `883926` / `883409` |
| code | str | `600000.SH`（iFinD 代码，带后缀） |
| name | str | 证券简称 |

### 4.2 日线宽表 `data/proc/daily_wide.pkl`（回测内存形态）

- index=trading_day，columns=MultiIndex(code, field) 或 dict{field: DataFrame}；
- field ∈ {open, high, low, close, volume, amount, turnover, pct_chg}（前复权）；
- 缺失（停牌/未上市）= NaN，由 vbt 处理为不可交易。

### 4.3 因子面板 `data/proc/factor_panel.parquet`

长表：`signal_date × code × factor_name × factor_value`，signal_date 即 T-1（因子可用的日期）。

### 4.4 目标持仓 `data/proc/target_holdings.parquet`

| 列 | 说明 |
|----|------|
| entry_date | T（入场日） |
| code | 股票 |
| weight | 目标权重 |
| entry_px | 预期入场价（回测=开盘价；精确验证环节=9:35价） |

## 5. 回测层设计（L4 细节）

### 5.1 A 股制度约束的实现

| 约束 | 实现 |
|------|------|
| T+1 | 持仓期强制 ≥1 天：入场 T（9:35/开盘价），出场 T+1 开盘价，不做日内往返 |
| 涨停不可买 | 板块感知一字判定：主板 ≥9.5%、创业板/科创板 ≥19%、北交所 ≥29%（模型经 gap_norm 特征隐式处理） |
| 跌停不可卖（罕见） | 同上板块感知阈值；v1.2 简化为正常卖出 |
| 成本 | 佣金 0.025%×2 + 印花税 0.05%（卖）+ 滑点 0.2%×2，全部折进价格调整或 fees/slippage 参数 |

### 5.2 vectorbt 用法

- 主口径 `Portfolio.from_orders`：直接给「每 entry_date 对每 code 的目标权重」订单块，size 以 `%` 形式给出，`group_by=entry_date` 实现每日组合等权、日间全仓轮动（天然满足 T+1：T 买 T+1 卖）。
- 对照口径 `Portfolio.from_signals`：简单的 entries/exits 布尔信号（用于和手写核对）。
- 产出：总收益/年化、最大回撤、夏普、胜率、盈亏比、换手、单日持仓明细 `pf.trades` / `pf.orders`。

### 5.3 基准

- 中证全指或沪深300 同期净值（qlib 仓 sh000300）；
- 「三池等权、每日全买」的朴素基准（检验选股是否真有增量）。

## 6. 错误处理与健壮性

- 抓取层：单票失败重试 2 次，仍失败则记入 `data/raw/_failed.log`，不阻塞整体；池子接口 errorcode≠0 直接抛异常（口径问题必须人工介入）。
- 停牌/退市：日线缺行 → 因子 NaN → 选股层跳过；已持仓票出场日无数据 → 以最后可得价格平仓并标记。
- 限流：iFinD 池接口逐日串行；qlib 仓本地读取无限流。
- 所有脚本幂等：文件存在即跳过（`--force` 重抓）。

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 1 分钟数据仅 5 日 → 9:35 因子结论样本不足 | 明确定位为「管道验证 + 初筛」，不做统计显著性断言；实盘脚本可持续积累数据 |
| 开盘价近似 9:35 入场的偏差 | 在 5 日窗口上量化两者差异分布（实验 E3 输出） |
| 热股池涨停多、可交易性差 | A4 一字过滤 + 成本敏感性实验 E4 |
| 过拟合 | 本期不跑参数网格；Top-N/出场规则只做少量离散对照并如实报告全部结果 |
